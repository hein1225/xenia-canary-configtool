## 三、关键发现与修复

本轮共 5 个提交，其中 4 个是修复 CI 暴露的真实缺陷。所有缺陷有一个共同特征：
**本地能过、CI 必挂**，根因是本地用了真实文件、装了额外工具或屏幕尺寸不同。

### 1. 测试对显示分辨率有隐性依赖（推 CI 前发现）

第 [10] 项把窗口设为 1500x950 且强制 `scaling=2.0`，最长键名需 625px 列宽；
屏幕不足 1600px 时 Tk 压到 606px，报出「列宽不足」的假失败。

对照实验：

| 环境 | 结果 |
|---|---|
| 实机（用户昨天测） | 41/41 |
| Xvfb 1920x1080 | 41/41 |
| Xvfb 1280x800 | 40/41（误报） |

用昨天交付的 AppImage 解包后的解释器跑同一测试，在 1280x800 下同样失败，
证明与今天的重建无关。

修复：测试自检显示环境，不足 1600x1000 时自动拉起 Xvfb，结束清理。

### 2. CI 缺 tomllib（run #1 失败）

`ubuntu-22.04` 自带 Python 3.10，而 `toml_edit.py` 与 `test_e2e.py` 都用标准库
`tomllib` 校验 TOML（Python 3.11+）。导入阶段即 `ModuleNotFoundError`。

修复：runner 升级为 `ubuntu-24.04`（Python 3.12）；libfuse2 在 24.04 更名
`libfuse2t64`，改为两个包名依次尝试；测试脚本加 Python 版本前置检查，
给出可读提示而非一行难以定位的 import 错误。

### 3. 测试隐式依赖本机用户配置（run #2 失败）

第 [10] 项构造应用实例后，应用会去 `$HOME/.config` 找用户真实配置。开发机
上恰好存在（昨天调试留下），CI 上没有，于是报「卡片 12 实列 0」——看上去
像程序缺陷，实为测试依赖机器状态。

修复：显式加载仓库自带的 `reference.config.toml`。验证方式是把本机用户配置
临时移走模拟干净环境，由 40/41 变为 41/41，分组数从 21 恢复为 22。

### 4. 列宽断言误报（run #3 失败）

CI 报「Video: 值只需 29 却占 70」。查 `app.py:1537`：
`val_min = max(70, _text_width("当前值", bold=True) + pad)`——「当前值」三个
粗体汉字恰好约 70px，**这是防止表头被截断的必要下限，不是缺陷**。

修复：判据把下限纳入比较，下限按当前语言表头实测而非写死；容差由 2px 放宽
到 8px 以吸收字体度量差异。并做了反向验证确认判据没被削弱——值短却白占
150px、value 远超 modified 等真实缺陷仍会被抓出。

### 5. AppStream 校验导致拒绝打包（run #4 失败）

`appimagetool` 会调 `appstreamcli` 校验元数据，2 个 warning 即拒绝打包。
本机没装 `appstreamcli` 所以跳过了校验，问题只在 CI 暴露。

修复三处：

- id 改为不含连字符的反向域名（原值触发 `cid-rdns-contains-hyphen`）
- 打包时从 XML 解析 `<id>` 并以它作为 metainfo 文件名，使文件名与 id 永不脱钩
- 移除 `<ul>` 上的 `xml:lang`，改标在 `<li>` 上（原写法触发
  `description-enum-group-translated`）

本机装上 `appstreamcli` 后可完整复现该校验，现为 `✔ 验证成功`。

### 6. CI 产物混入 35MB 无用开发文件（全绿后主动排查发现）

对比本地与 CI 产物体积：19MB vs 27MB。定位到 CI 环境装有 `python3-dev`，
`$prefix/lib/pythonX.Y/` 下多出 `config-X.Y-<triplet>/`，内含：

- `libpython3.12.a` — 14.0 MB 静态库
- `libpython3.12-pic.a` — 12.7 MB 位置无关静态库
- `libpython3.12.so` — 8.6 MB 开发用共享库

运行期完全用不到。修复后 CI 产物 **27.2 MB → 17.8 MB**，缩减约 35%。

验证方式：构造 26MB 假静态库模拟 dev 环境，确认宿主存在该目录时包内不再
混入，且宿主标准库本身不受影响。

## 七、可复用经验

1. **本地能过 CI 必挂的根因通常是环境差异**：真实文件、额外工具、屏幕尺寸。
   写 CI 前应先问「干净机器上有什么」，而不是「我机器上有什么」。
2. **构建依赖被隐式发现不可靠**。`appstreamcli` 这类工具在就装、不在就跳过，
   等于 CI 才暴露问题。本地应主动安装与 CI 一致的工具链以复现。
3. **断言误报比漏报更伤**。修复误报时必须做反向验证，确认真实缺陷仍能被
   抓出，否则是把测试改废了。
4. **体积差异是发现打包缺陷的线索**。同类产物在不同机器上大小不同，往往
   说明捆绑了编译期才需要的文件。
5. **AppStream 的 `<id>` 必须与 metainfo 文件名一致**，且不能含连字符；
   用脚本从 XML 解析 id 作为文件名可根治此类错配。
6. **凭据不要写进 remote URL 长期保留**，Push 后立即还原，并扫描
   `.git/config`、提交历史、shell 历史确认无残留。
